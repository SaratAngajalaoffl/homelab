# netbird Stack Context

## Glossary

**netbird-stack** — compose project `netbird-stack` in `containers/netbird/`. Combined NetBird server (management+signal+relay+STUN) + dashboard.

**k8s migration** — `~/homelab/helm/netbird/` holds this stack's Helm chart, converted per `docs/adr/0004-kubernetes-migration.md`. Two Deployments via `helm/homelab-common` (`netbird-server`, `netbird-dashboard`), one **custom multi-path Ingress** (`helm/netbird/templates/ingress.yaml`, not the shared `homelab-common.ingress` helper — this is the first stack needing more than one backend service on the same host). Live production deployment as of 2026-09-06; Compose stack was already stopped before this migration.

**Multi-path Ingress replicates NPM's Advanced-tab location blocks** — the old NPM config (`npm-advanced-config.txt`) routed `/relay`, `/ws-proxy/`, `/signalexchange.SignalExchange/`, `/management.ManagementService/`, `/api/`, `/oauth2/` to `netbird-server` and everything else to `netbird-dashboard`, using nginx `location ~ regex` blocks. Standard k8s `Ingress` `pathType: Prefix` covers this exactly (these are literal string prefixes, not real regex, despite the dots in the nginx pattern) — no need for Traefik's `IngressRoute` CRD. Traefik proxies gRPC, HTTP/2, and WebSocket natively with no special annotations (unlike NPM's nginx, which needed "HTTP/2 Support" toggled and explicit `Upgrade`/`grpc_pass` directives).

**STUN raw UDP via `hostPort`** — extended `helm/homelab-common/templates/_deployment.tpl` with a new generic `extraPorts` field (raw containerPort entries, supporting `hostPort`/`protocol`) since STUN is plain UDP and can't go through Traefik's HTTP(S) proxying, same category of exception as Compose's `3478:3478/udp` port publish. `values.yaml`'s `server.extraPorts` binds `3478/udp` straight to the k3s host — **single-node-only**, same caveat as jellyfin's media `hostPath`. This generic field is now available to any future stack with a similar raw-UDP/TCP port need (e.g. `arr`'s gluetun utility ports).

**Fresh-install trap caught before data copy** (same pattern as nextcloud) — `helm install` brought the server up healthy, but its logs showed `fresh install detected, using default domain` and `accounts number 0` — an empty PVC gets a brand-new SQLite store on first boot. Fixed by: scaling `netbird-server` to 0, temporary `busybox` pod on the PVC, wiping the fresh `/var/lib/netbird`, streaming the real data in directly from the Compose stack's Docker named volume (`docker run --rm -v netbird_netbird_data:/vol alpine tar -cf - -C /vol . | kubectl exec -i ... -- tar -xf -`, since this volume was never a host bind mount), deleting the busybox pod, scaling back to 1. Post-restart log confirmed `single account mode enabled, accounts number 1` — real data loaded.

**Data migration (verified)** — 5 files, 70MB total (`store.db`, `idp.db`, `events.db`, plus the two GeoLite2 DBs), all present after copy; md5sum matched exactly on the three DB files that matter (`store.db`, `idp.db`, `events.db`) between the source Docker volume and the restored PVC. Verified externally: dashboard 200, `/api/accounts` returns 401 (reaches `netbird-server`, not a proxy error), `/oauth2/.well-known/openid-configuration` returns 200 with the correct issuer — confirms all three path classes (dashboard catch-all, API, oauth2) route correctly.

**Secrets** — `netbird-config` (the entire `config.yaml`, mounted as a file via a `secret` volume + `subPath`) and `netbird-dashboard-env` (all of `dashboard.env`'s keys via `envSecretName`/`envFrom`) are both `SealedSecret` manifests (`helm/netbird/templates/sealed-*.yaml`). Sealed directly from the existing Compose files by piping them into `kubeseal` — contents were never displayed and no plaintext `Secret` object was created in-cluster. `config.yaml`'s `server.reverseProxy.trustedHTTPProxies` was changed from NPM's old static edge-network IP (`172.22.0.9/32`) to the k3s pod CIDR (`10.42.0.0/16`, confirmed via `kubectl get pods -A -o wide`), since Traefik's pod is now the proxy hop and its IP isn't fixed.

**Native host peer unaffected** — this host's own `netbird` systemd client (WireGuard peer, not part of either compose or this chart) was already pointed at `https://netbird.smugiwara.com`; no change needed since the domain and cert didn't move.
