# hermes Stack Context

## Glossary

**hermes-stack** — compose project `hermes-stack` in `containers/hermes/`. Self-hosted Hermes Agent personal AI assistant.

**k8s migration** — `~/homelab/helm/hermes/` holds this stack's Helm chart, converted per `docs/adr/0004-kubernetes-migration.md`. One Deployment (`server`, two containerPorts: `8642` API, `9119` dashboard) via `helm/homelab-common`, two Services (one per port), two Ingresses: a plain `homelab-common.ingress` for the dashboard (app enforces its own basic auth internally, no Traefik middleware needed) and a bearer-token Traefik `IngressRoute` for the API (same `HeaderRegexp` pattern as `helm/ollama`). Live production deployment as of 2026-09-06; Compose stack was already stopped before this migration.

**Two real (pre-existing, not migration-caused) bugs surfaced and fixed**:

1. **API server was bound to loopback-only** — the real `hermes.env` only has `HERMES_DASHBOARD_BASIC_AUTH_USERNAME`/`_PASSWORD` and `HERMES_API_SERVER_KEY`; it's **missing** `API_SERVER_ENABLED`/`API_SERVER_HOST=0.0.0.0`, which the stack's own `.example`/`.setup` document as required for the API server to bind non-loopback. Without them the app defaulted to `127.0.0.1:8642` — reachable from inside the pod itself, but not from Traefik or any other pod (confirmed via `/proc/net/tcp`: `0100007F:21C2` before the fix, `00000000:21C2` after). **This means the API server was very likely also unreachable cross-container under the old Compose setup** — NPM's proxy target `hermes_gateway:8642` would have hit the same loopback-bind wall. Fixed by adding `API_SERVER_ENABLED: "true"` / `API_SERVER_HOST: "0.0.0.0"` as explicit non-secret env vars in `values.yaml`.

2. **Wrong env var name for the gateway's own API key** — the app's internal auth check reads `API_SERVER_KEY` (unprefixed), but `hermes.env` only defines `HERMES_API_SERVER_KEY` (prefixed) — a naming drift from the documented convention. This meant even with the network fixed, the app's own key check would reject every request as `gateway_auth_error`. **Also likely broken the same way under Compose** — NPM's Advanced-tab snippet did its own separate token comparison at the nginx layer and never actually depended on the app validating the same header, so this went unnoticed. Worked around by adding a second key `API_SERVER_KEY` (same value) directly into the sealed secret alongside the original `HERMES_API_SERVER_KEY`.

3. **The gateway's real API key isn't `hermes.env`'s value at runtime anyway** — `/opt/data/.env` (written by the interactive `hermes setup` wizard, migrated as part of the state directory) takes precedence over both container env vars at startup (confirmed via a startup log line: `"API_SERVER_KEY is set in both the container environment and /opt/data/.env — the .env value wins at runtime"`). **The actual bearer token clients need to use is the value inside the migrated `/opt/data/.env`, not `hermes.env`'s `HERMES_API_SERVER_KEY`** — these were already two different values before migration too. If any existing external client was built against `hermes.env`'s key, it needs updating to the `/opt/data/.env` value (`kubectl exec -n homelab-hermes <pod> -- grep '^API_SERVER_KEY=' /opt/data/.env`, run directly by a human — not something to script into a chart since it's cluster-runtime state, not a repo secret).

**Data migration via hostPath-mounted root pod, not a direct host tar** — `homelab-conf/hermes/state` is owned by uid/gid `10000` (the image's built-in `hermes` user) with `700`-ish permissions, unreadable by the operator's own host user. Since a plain `tar -C <hostpath> ...` as a normal user would hit `Permission denied`, the migration instead used a temporary pod with a **read-only `hostPath` mount of the source directory** running as root (k8s pod default) alongside the destination PVC, and did the copy (`cp -a`) entirely inside that pod — root inside a container can read any host file regardless of host-side ownership. This is a new pattern worth reusing for any future stack whose state dir isn't owned by the operator's own uid.

**Data migration (verified)** — 53869 real files (3.3GB — `config.yaml`, `.env`, `state.db`/`response_store.db`/`runs_idempotency.db` + WAL/SHM, `memories/`, `skills/`, `sessions/`, `cron/`, `hooks/`, `logs/`, `SOUL.md`, plus assorted workspace scratch files). 2 "extra" files on the destination (`.clean_shutdown`, `.install_id.lock`) were confirmed to be artifacts from the temporary fresh-install boot before the wipe, not real data — verified via full path diff, not just count. md5sum matched exactly on `config.yaml` and `state.db`. `chown -R 10000:10000` applied after copy (the migrate pod's `cp -a` ran as root, so ownership needed restoring to match the image's expected user).

**Verified externally**: dashboard → 200 (follows a 302 login redirect, Hermes' own app-level auth, not an HTTP 401 challenge like NPM's Basic Auth was); API with the correct (`/opt/data/.env`-sourced) bearer token → reaches the app and passes its auth check (confirmed via app-level 404 for an unregistered path, vs. `gateway_auth_error` for a wrong key). Telegram integration reconnected successfully post-migration (`"Connected to Telegram (polling mode)"` in logs), confirming the bot token in the migrated `.env` is intact and live.

**Secrets** — `HERMES_DASHBOARD_BASIC_AUTH_USERNAME`/`_PASSWORD`, `HERMES_API_SERVER_KEY`, and the added `API_SERVER_KEY` are a `SealedSecret` (`helm/hermes/templates/sealed-secrets.yaml`), sealed directly from `hermes.env` plus one appended line — never displayed, never a plaintext in-cluster Secret. The API IngressRoute's bearer token (Traefik's edge-level `HeaderRegexp` gate, `values.secret.yaml`) was deliberately set to match `/opt/data/.env`'s real `API_SERVER_KEY` value (not `hermes.env`'s `HERMES_API_SERVER_KEY`, which the app doesn't actually honor per bug #3) — so as of this migration there is exactly **one** token a client needs, unlike the two-different-keys situation this surfaced initially. Verified end-to-end: `curl .../v1/models` with that one token returns a real model list through both gates.
